
External Locations:
-------------------

We have a new type of object that unity catalog supports is-->External location

Create an external location to an existing container (or) directory in ADLS
using catalog explorer and also we can create by writing code also

External location is like your dbfs mounts,

create an external location,map it to your ADLS storage container and
you can access data files from that container from within the databricks

Advantage of External Location over DBFS mounts
-----------------------------------------------
-here the advantage is,once you create the external location, you can 
 provide privilages on that external location and manage privilages from
 unity catalog
 but in DBFS mounts--->all users can access-->that is the dis-advantage

metastore--->Top most object
             already we created this from databricks account console

             inside metastore--->we create catalog-->2nd level

             within catalog--->we create database/schema --->3rd level

             within database--->we create tables,views,volumes,functions->4th level


see the diagram-->
External locations and storage credentials are not part of schema/database

In Unity-catalog--->Privilages are in-herited

If privilage added on catalog level--->they are inherited to schema--->
 --->from schema inherited to tables,views,volumes i.e all objects in schema

ex:
 in DEV catalog--->If you have assignes privilages to someone
                   -here if 3 databases are created-->then you get all the
                     privilages to all the 3 databases and its objects(tables,views,volumes etc)

This is in-heriting privilages from higher level to lower level

we can grant privilages at--->catalog level
                              schema/database level
                              table/volume    level
